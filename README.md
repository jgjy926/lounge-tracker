# Lounge Tracker

Tracks credit-card airport lounge access: which card gets you into which lounge, on what
terms, how many visits are left, and what you still need to spend. Android app and web page
from one codebase, running entirely on free tiers (GitHub Pages + Cloudflare Workers + Koofr).

```
Web page (GitHub Pages)  ─┐
                          ├─ Cloudflare Worker (token check, secrets) ─ Koofr (WebDAV)
Android app (Capacitor)  ─┘                    └─ Workers AI (Ask wording only)
     ⇅
IndexedDB (works offline)
```

## How the answers work

`frontend/src/lib/engine.js` is the only source of eligibility answers. It is pure code with
no AI in it. The tests include every worked example in AEON's August 2026 T&C.

| Answer | Meaning |
| --- | --- |
| Eligible | The saved terms are met by the recorded spend and visits |
| Eligible if you spend | Still possible, with the shortfall and the last day |
| Unclear | The answer depends on something the T&C doesn't state, or the rule is over 180 days unchecked |
| Not eligible | A stated term rules it out |
| Not covered | No rule for this card and lounge or date |

A `null` in a rule means "the T&C doesn't say". The engine works out the condition twice,
strictly and generously. Met on strict is Eligible; met only on generous is Unclear.

AI is used in two places, and neither can change an answer:
- **Import:** copy a prompt into any AI chat and paste the JSON back: a bank T&C, lounges, card
  spend or an e-ticket. You review it before anything saves. The lounge prompts read only the
  bank's document, never the web. See [docs/ai-prompts.md](docs/ai-prompts.md), generated by
  `npm run prompt:doc`.
- **Ask:** the app answers from the engine first, offline. With the cloud on, Workers AI also
  explains that result in words.

## How lounges and cards link

Each bank has its own T&C, and that T&C sets the lounges its card can use. A rule keeps the result:

- `lounge_scope: 'specific'`: only the lounges in `lounge_ids`, when the T&C limits access to them.
- `lounge_scope: 'network'`: any saved lounge in the rule's programme, when the T&C says the whole
  programme counts. `sameProgramme` ignores wording such as "Lounge".

Importing a T&C fills this in from the lounges it names. If they're in a separate document, Import
> Lounges reads it and attaches them to the card you choose. One lounge record can sit on several
cards' lists. A new T&C that names no lounges keeps the card's current list. Library > Banks shows
each bank's cards with their T&C and eligible lounges, and Find searches saved lounges and groups
your cards by answer.

## Trips and reminders

A trip is one departure, so a return flight is its own trip. `frontend/src/lib/trips.js` plans
upcoming trips in date order, and each one's chosen card counts as a visit for later trips. For
spend still needed, it works out when the window opens, the last day before the flight and the
last day the T&C allows.

Android schedules reminders on the device when the window opens, 7 days before the deadline and
the day before, at 9am. They are rescheduled whenever the data changes, so they stop once the
requirement is met. A browser can't do this, so the Trips tab offers a calendar file instead.
Those calendar entries are a snapshot and don't update.

## Develop

```bash
cd frontend
npm install
npm test
npm run dev
```

The app runs fully local until a Worker URL and token are entered in Settings.

To try the whole stack with no Koofr account, copy `worker/.dev.vars.example` to
`worker/.dev.vars`, then run each of these in its own terminal:

```bash
node worker/test/fake-koofr.mjs
```

```bash
cd worker && npm install && npx wrangler dev --port 8787 --var KOOFR_DAV_BASE:http://localhost:8788/dav
```

## Deploy

See the Lounge Tracker setup guide for the full steps.

```bash
cd worker
npm install
npx wrangler deploy
```

Then set the secrets with `worker/scripts/set-secrets.ps1`. It asks for your Koofr details,
checks them, generates the access token and copies it to the clipboard.

The web page deploys through `.github/workflows/deploy.yml` on push to `main`. Set the repo
variable `WORKER_URL` to pre-fill the URL in Settings, and enable GitHub Actions as the Pages
source. If the Pages origin isn't `https://jgjy926.github.io`, change `ALLOWED_ORIGIN` in
`worker/wrangler.toml`.

## Android

Needs Android Studio for its JDK and SDK. In PowerShell:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
```

```bash
cd frontend && npm run android:apk
```

The output is `android/app/build/outputs/apk/debug/app-debug.apk`. Rebuild after any frontend
change. The APK holds no token, since each device enters its own in Settings.

To change the icon, edit `frontend/scripts/make-icons.py` and run `npm run icons`, not the
output files. If Gradle then reports a missing `ic_launcher_foreground`, run `gradlew clean` once.

## Security

- The Koofr credentials live only on the Worker, as secrets.
- The access token is never in the web bundle or the APK. It stays in the device's storage.
- Every Worker route checks the token. CORS allows only the Pages origin and localhost.
- Store the last 4 digits of a card at most, never a full number.

## Sync

Edits save to IndexedDB at once and push after 3 seconds, or immediately when the app goes to
the background. The Worker refuses a save based on an out-of-date copy, so the app asks which
copy to keep instead of overwriting. The first save each day keeps a dated copy in
`LoungeTracker/backups/`, and choosing "keep this device" also keeps the copy it replaced.
Backups aren't pruned automatically.
